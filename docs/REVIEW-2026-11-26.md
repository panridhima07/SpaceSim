# ASTRA review: judge, investor and bystander pass (26 Nov 2026)

About 18:34 to 20:00. Reviewers read the code as a hackathon judge, a technical investor and a first-time visitor. Each verified finding went to an agent with a written brief. Every change was reviewed and tested before it was accepted. Nothing was committed or deployed.

Two other sessions were working in the same checkout: "Manual control system UI" (src/app, src/landing) and "Physics agent issues" (src/physics, rocket-physics, src/mission). Findings in their files were sent to them, and they fixed most of them on their side.

## Fixed in this session

### First impression and demo safety
- One exception in the render loop no longer freezes the app (`src/app/main.ts` frame/frameBody).
- A failed app load (for example no WebGL) shows a readable screen with a Reload button instead of a blank page (`src/app/fatal.ts`, both boot files).
- "Continue as guest" is remembered for the tab, so the Moon page and reloads no longer show the sign-in wall again. A build with no Supabase settings now opens in guest mode instead of a dead end (`src/auth/gate.ts`).
- An expired or already-used email or Google sign-in link now says so. Android callback errors show plain text.
- Clearer labels and help: "TRY THE SAMPLE ROCKET", "FLY ISRO'S LVM3", tooltips on stability margin, rail azimuth and ejection delay, empty-state hints, and keyboard access to the phone HUD bar.
- Pinch-zoom is allowed again. Titles, descriptions and social preview tags are added, and the app is named "ASTRA Spaceflight" everywhere except the in-app brand bar (src/app/ui.ts), which still says "Space Flight Builder" and was reported to the UI session.
- parts.html (part gallery) and presentation.html (pitch deck) are now built; they returned 404 on the live site before. The deck's Print button now works under the page CSP.
- The sign-in journey no longer downloads about 4.3 MB of planet textures and star data before first paint. It loads them when the visitor scrolls, or after 4 s.

### Honesty of claims
- presentation.html: removed "mobile game ... from Mercury to Jupiter", corrected test counts, accuracy numbers, the .eng export claim, the flaw list and the roadmap.
- README and SYSTEM_DESIGN: the live URL, the real deploy chain, test counts, pages, migrations and guest mode are now stated correctly. The "same-origin" claim for /api/simulate was reworded to match the code.
- Added `docs/DEMO.md` (a 3-minute judge demo path with known limits) and `THIRD_PARTY_NOTICES.md`.

### Security and privacy
- Security headers: frame-ancestors none, X-Frame-Options, nosniff, Referrer-Policy and Permissions-Policy. They are set for prebuilt deploys (`scripts/build-vercel-output.mjs`) and for Git builds (`vercel.json`).
- The service worker no longer caches /api or /app-update, and its cache name changes with every build.
- Consent: an answer is tied to the account or guest that gave it, so a new account on the same browser no longer inherits it. A failed withdrawal is re-sent on the next start. Escape on a reopened dialog keeps the earlier answer instead of silently withdrawing an opt-in. Guests are no longer interrupted by the popup.
- The Android APK updater now checks the download host natively, not only in JavaScript.
- /api/simulate: the token shape is checked before Supabase is called. A sign-in check that cannot run no longer fails signed-in users with a 503. Each kind of job has a CPU budget below the client's timeout. The rate limit no longer trusts the client-sent `x-forwarded-for`.
- The landing result card is built with textContent instead of innerHTML. Debug hooks only exist in dev.
- New migration `supabase/migrations/0004_row_and_size_caps.sql` (**not applied**): per-user row caps (upserts of existing rows are let through), JSON size limits, storage paths limited to the user's own folder, a missing foreign-key index, and a fixed search_path plus revoked EXECUTE on trigger functions.

### Data integrity and correctness
- Cloud sync: a deleted rocket no longer comes back after a failed delete. A failed account save no longer shows "saved to your account". Store writes now report whether they succeeded.
- Saving a 41st rocket used to delete the oldest one silently. It now asks the user to delete one first. Design ids can no longer collide.
- Importers:
  - The default motor configuration is now the one used.
  - OpenRocket "after" positioning works.

  - RockSim: warnings for stages and motors that are not imported, and the correct streamer length.
  - BOM-less UTF-16 files are read.

- Builder:

  - A part can no longer start ahead of its parent.

- Lunar: one Moon GM value (GRAIL), a working fallback when the worker fails, finer steps on the first manual burn, partial thrust on the step where propellant runs out, and leftover simulation time is carried over instead of dropped.

- Rendering and memory: orbit lines are no longer rebuilt every frame at high warp, InstancedMesh, launch-site and WebGL context disposal are fixed, and per-frame allocations are removed.

## Open items that need a decision
1. **Usage tracking consent (privacy/legal).** `src/cloud/usage.ts` keeps a persistent device id and logs app opens without opt-in. DNT and GPC are the only gates. Under GDPR/ePrivacy this probably needs consent. Decide between opt-in and the current opt-out.
2. **Apply migration 0004** with `supabase db push` after reviewing it. In the Supabase dashboard also turn on CAPTCHA and email confirmation for sign-up; per-account caps do not stop many free accounts. Usage analytics (0003) can be filled by anyone with the anon key. Real protection needs a server-side proxy.
3. **Live-update signing (Android).** The web bundle's sha256 only detects corruption. Anyone who can deploy to Vercel or push to `main` can ship code to every installed app. Sign the manifest with an offline Ed25519 key, and keep the public key in the native build.
4. **The Git-connected Vercel project.** A push to `main` deploys to production without the Supabase env vars, which replaces the `npm run deploy` build. Set the env vars in Vercel, or turn off Git production deploys.
5. **Licence.** There is no project LICENSE. The planet textures and `slide1_space_panel.jpg` have no recorded source. Add the d3-celestial BSD-3 text. See `THIRD_PARTY_NOTICES.md`.
6. **Physics items left open by the physics session** (they change validated numbers):
   - Supersonic fin-lift scaling.
   - Reynolds number at altitude.
   - Atmosphere above 86 km and the geopotential conversion.
   - Nose-shape dependence of wave drag.
   - Crush load using the mass ahead of each tube.
   - Falcon 9 MVac thrust (934 kN is the pre-Block-5 figure; 981 kN brings SECO from T+539 s to 524 s against the reference 517 s).
   - The LVM3 "reference events" test checks the sim's own times. Fairing jettison is 42 s early against ISRO's timeline.
7. **Gameplay choices.** Moon landing limits are looser than Chandrayaan-3's (4.5 m/s vertical against about 2 m/s real). The 24/38/54 mm motor mounts don't fit the tubes the catalogue pairs them with; only the comments were corrected.
8. **Pitch deck .pptx.** The binary deck still has the old claims. Only presentation.html was corrected.
9. **Repo hygiene.** Four empty `*.txt` name files at the root, a duplicate `ASTRA_Spaceflight_Presentation.ppt` next to the `.pptx`, and leftover per-task logs in `docs/`. Delete them if you want a cleaner repo.
